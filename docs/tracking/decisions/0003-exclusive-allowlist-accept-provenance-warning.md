# 0003. `plugins.allow`를 켜진 목록에서 계산해 설정하고, 남는 출처 경고는 감수한다

## 맥락

패치된 OcuClaw는 OpenClaw의 "출처를 확인할 수 없는 플러그인" 경고를 낳는다. 경고를 줄이는 공식 수단은 `plugins.allow`인데, 이 목록은 배타적이라 설정하는 순간 목록 밖 플러그인이 모두 꺼진다. 당시 켜진 플러그인은 40개가 넘었고, 내장 브라우저는 Aside로 대체하기로 했으며, 로컬 임베딩용 llama.cpp 플러그인을 새로 켜야 했다.

## 결정

허용 목록을 손으로 적지 않고 `openclaw plugins list --enabled --json`의 현재 목록에서 `browser`를 빼고 `ocuclaw`와 `llama-cpp`를 더해 계산한다(지금 44개). 목록 일치는 검사 스크립트로 확인한다. 허용 목록에 넣어도 남는 출처 경고(패치된 파일은 검증할 수 없음)는 알려진 사항으로 두고 감수한다.

## 대안

- **허용 목록을 두지 않기**: 기존 플러그인이 꺼질 위험은 없지만 경고가 그대로고, 어떤 플러그인이 켜져 있어야 하는지의 기준이 없다.
- **필요한 몇 개만 적은 짧은 목록**: 나머지 수십 개 플러그인(채널, 공급자, 도구)이 조용히 꺼진다.
- **출처 경고가 나지 않도록 설치본을 패치하지 않기**(OpenClaw 버전 낮추기나 중간 변환 서버): 버전 낮추기는 상태 DB 마이그레이션 때문에 위험했고, 중간 변환 서버는 tick 키·미지원 메서드 버그를 못 고친다. 경고 하나를 없애려고 버그 수정을 포기할 수 없었다.

## 결과

- 허용 목록이 생긴 뒤 새로 설치한 플러그인은 켜진 목록에 나오지 않으므로, 계산식의 포함 목록에 명시해야 켜진다.
- `browser`가 빠져 `browser.request`를 부르는 클라이언트는 "unknown method"를 받는다. 내장 브라우저를 다시 쓰려면 허용 목록과 `browser.enabled`를 함께 되돌려야 한다.
- 출처 경고는 Gateway 로그에 계속 남으므로, 로그 점검 때 이 경고를 문제로 다루지 않는다. 대신 로드 거부는 즉시 되돌릴 사유다.
