# 0008. 리체에게서 Aside를 빼고, 대신할 브라우저 도구를 붙이지 않는다(0005 대체)

## 맥락

2026-10-30 사용자가 Aside 브라우저를 쓰는 모든 Mac에서 빼기로 했다. 이 Mac에서도 Aside 앱과 `aside` CLI가 지워지므로, 설정에 `mcp.servers.aside`가 남으면 없는 실행 파일을 자동 승인(`approve`)으로 가리키는 MCP 서버가 남고, 저장소의 적용 스크립트를 다시 돌리면 그 서버가 다시 등록된다.

사용자는 에이전트의 웹 작업을 에이전트 브라우저(ego lite, `ego-browser` 명령) 하나로 모으기로 했다. 이 브라우저는 스크립트를 넘겨 실행하는 방식이고 MCP 서버 모드가 없어 OpenClaw MCP 서버로 그대로 붙일 수 없다. 0005의 자동 승인은 Aside라는 한 도구에 대해 사용자가 위험 설명을 듣고 고른 것이고, `docs/security.md`는 자동 승인을 다른 MCP 서버로 넓히지 않는다고 정해 두었다.

## 결정

- 리체에게서 Aside MCP 서버를 뺀다. `scripts/apply-memory.sh`(옛 이름 `apply-memory-aside.sh`)는 Aside를 등록하지 않고, 예전 판이 남긴 `mcp.servers.aside`가 있으면 `openclaw mcp unset aside`로 지운다. 없으면 건너뛰므로 다시 돌려도 결과가 같다.
- 대신할 웹 도구는 붙이지 않는다. 내장 브라우저는 계속 꺼 둔다(`browser.enabled = false`, 허용 목록에서 제외). 리체에게 브라우저 도구가 없는 상태가 된다.
- 0005를 대체한다. 0005의 자동 승인 정책은 Aside와 함께 없어지며 다른 도구로 옮기지 않는다.

## 대안

- **에이전트 브라우저를 리체의 도구로 붙이기**: MCP 서버 모드가 없어 감싸는 서버를 새로 만들어야 하고, 로그인된 계정을 다루는 도구의 승인 정책을 사용자가 새로 정해야 한다. 0005의 자동 승인을 그대로 옮기는 것은 보안 정책에 어긋난다. 사용자가 정하지 않았다.
- **내장 브라우저 다시 켜기**: 붙을 Chrome이 없어 실패했던 경로이고(0005의 맥락), 웹 작업에 브라우저 하나만 쓴다는 사용자 원칙과 어긋난다. 허용 목록도 함께 되돌려야 한다.
- **설치본에서만 지우고 저장소는 그대로 두기**: 다음에 적용 스크립트를 돌리면 없는 실행 파일을 가리키는 Aside가 자동 승인과 함께 다시 등록되고, 문서와 설치본이 어긋난다.

## 결과

- 로그인된 사이트에서 무언가를 해 달라는 요청(Hey Even 음성 포함)은 리체가 할 수 없다.
- 0005가 받아들였던 위험(잘못 알아들은 음성이나 웹 페이지 속 지시문 때문에 확인 없이 일어나는 쓰기 동작)이 없어진다.
- 웹 도구를 다시 붙이려면 사용자가 붙일 도구와 그 승인 정책(확인 없이 실행할지, 동작마다 확인받을지)을 먼저 정하고 새 결정으로 남긴다.
- 이 변경 전에 만든 백업의 `openclaw.json`에는 `mcp.servers.aside`(자동 승인)가 들어 있다. 그런 백업으로 복원했으면 `scripts/apply-memory.sh`를 다시 돌려 지운다.
- `apply-persona-locale.sh`는 처음 설치 뒤 달라진 성격 파일을 건너뛰므로, 저장소 `persona/AGENTS.md`의 브라우저 절을 고쳐도 설치본 workspace의 `AGENTS.md`는 저절로 바뀌지 않는다.
