# 0001. OcuClaw 버그는 설치본에 우리 코드를 끼워 넣어 고친다

## 맥락

OpenClaw 2026.10.5로 올라간 뒤 Hey Even 답이 첫 조각만 안경에 떴다. 원인은 Gateway가 assistant 프레임을 delta 전용으로 바꾼 것과 OcuClaw 2.1.2가 `text` 필드만 읽는 것의 조합이다. 같은 플러그인에 `sessions.compaction.list` 호출 오류와 tick API 키 조회 TypeError도 있었다. OcuClaw는 외부 배포 플러그인이고 라이선스가 표시되어 있지 않으며, 이 저장소는 공개된다.

## 결정

설치된 OcuClaw의 `dist/` 파일에 한 줄 훅을 기준 문자열 위치에 넣고, 로직은 우리가 쓴 모듈(`dist/ocuclaw-g2/`)에 둔다. 적용은 전부 아니면 전무, 멱등이며, 지점별 검사와 실측 비교 명령을 함께 둔다.

## 대안

- **OpenClaw를 이전 버전으로 낮추기**: 상태 DB 마이그레이션이 이미 진행되어 되돌리면 대화 기록·상태가 깨질 위험이 컸다. OpenClaw의 다른 수정도 함께 잃는다.
- **Even 앱과 OcuClaw 사이에 중간 변환 서버 두기**(패치 없이 응답을 기록 기준으로 바꾸는 프록시): 설치본을 건드리지 않는 장점이 있었지만, 경로·포트·인증을 하나 더 운영해야 하고 tick 키 버그와 미지원 메서드 호출은 고치지 못한다. 사용자가 패치 쪽을 골랐다.
- **고친 OcuClaw 파일 전체를 저장소에 두고 덮어쓰기**: 라이선스 표시 없는 원본 코드를 공개 저장소에 싣게 되어 불가.
- **OcuClaw 정식 수정 기다리기**: 그동안 Hey Even을 쓸 수 없다. 버그 보고는 따로 한다.

## 결과

- OcuClaw 업데이트마다 패치가 사라진다. 그래서 감시·알림과 재적용 명령이 필요하다.
- 패치된 플러그인은 원본과 달라 OpenClaw 출처 경고가 영구히 남는다.
- 새 OcuClaw 버전에서 기준 문자열이 바뀌면 사람이 설치본을 읽고 기준 문자열을 고쳐야 한다. 원본 코드는 여전히 저장소에 들일 수 없다.
- 패처 단위 시험은 저장소 밖 깨끗한 원본 사본에 의존하므로 다른 기계에서 그대로 돌 수 없다.
