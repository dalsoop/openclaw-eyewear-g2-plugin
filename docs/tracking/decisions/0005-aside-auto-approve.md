# 0005. 리체의 브라우저는 Aside이고, 쓰기 동작도 확인 없이 실행한다

## 맥락

OpenClaw 내장 브라우저는 로그인된 Chrome에 붙으려다 실패했다(이 Mac에는 Chrome이 없고 Aside와 Safari만 있다). 사용자는 처음에 평소 Chrome을 골랐다가 Aside로 바꿨다. Aside에는 사용자의 웹 계정들이 로그인되어 있고, `aside mcp`에는 자체 확인 단계 옵션이 없다. 리체는 안경 음성(Hey Even)으로도 불린다.

## 결정

Aside를 OpenClaw MCP 서버(`mcp.servers.aside`, stdio)로 등록하고 승인 정책을 `approve`(자동 승인)로 둔다. 내장 브라우저는 끈다(`browser.enabled = false`, 허용 목록에서도 제외). 이 정책은 위험 설명을 들은 사용자가 고른 것이다.

## 대안

- **Aside 쓰기 동작마다 확인 받기**: 안전하지만 안경·음성 경로에서는 확인할 화면이 사실상 없어, 웹 작업을 시키는 의미가 줄어든다. 사용자가 고르지 않았다.
- **로그인되지 않은 전용 브라우저 프로필**: 프롬프트 주입 피해 범위는 줄지만 리체가 사용자 계정으로 일을 할 수 없다. 사용자가 전용 브라우저를 고르지 않았다.
- **내장 브라우저 유지**: 붙을 Chrome이 없어 실패 경고만 남는다.

## 결과

- 잘못 알아들은 음성 한 마디나 웹 페이지 속 지시문으로 글 전송·설정 변경·결제가 일어날 수 있다. 이 위험은 문서화된 채 받아들여졌다.
- 이 정책을 더 안전하게(또는 더 넓게) 바꾸는 일은 사용자의 결정이 있어야 한다. 작업 중 임의로 승인 단계를 넣지 않는다.
- 내장 브라우저를 부르는 클라이언트는 "unknown method"를 받는다.
